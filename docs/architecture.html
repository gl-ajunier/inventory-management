System architecture

Two processes on localhost. The browser talks to the API directly over HTTP; CORS is open (allow_origins=["*"]).

Tech stack

Deliberately small: three runtime dependencies on each side.

Frontend client/

  • Vue 3 (Composition API, <script setup>)
  • vue-router 4 (HTML5 history)
  • axios for HTTP
  • Vite 8 dev server and build; Node 20.19+ or 22.12+
  • Charts drawn as hand-written SVG; layouts in CSS Grid
  • i18n in-house: English and Japanese, USD ↔ JPY at a fixed rate of 150

Backend server/

  • Python 3.11+, managed with uv
  • FastAPI with Pydantic v2 models
  • Uvicorn ASGI server
  • pytest + FastAPI TestClient (in tests/backend/)

Data server/data/

  • Static JSON files, no database
  • 3 warehouses: San Francisco, London, Tokyo
  • 5 categories: Circuit Boards, Sensors, Actuators, Controllers, Power Supplies
  • 4 order statuses: Delivered, Shipped, Processing, Backordered
  • generate_data.py regenerates orders.json only

Data flow: applying a filter

What happens when a user changes a filter on the Dashboard or Orders view.

Filter rules on the server

  1. Warehouse: exact match.
  2. Category and status: case-insensitive match.
  3. Month: substring match on order_date; accepts 2025-03 or a quarter key like Q1-2025.
  4. Inventory has no date, so it ignores the time filter.

Data lifecycle

  1. On startup, mock_data.py reads every JSON file into module-level lists.
  2. Requests only read and filter those lists; nothing is written back.
  3. Editing a JSON file needs a server restart. Changing a file's shape needs a matching Pydantic model change.

Known gaps

Places where the code doesn't match itself, found while mapping it.

Missing endpoints. api.js calls /api/tasks (used by the tasks menu in App.vue) and /api/purchase-orders, but the server implements neither, so those requests return 404.
Unrouted view. views/Backlog.vue exists but has no route in main.js.
Inconsistent API access. Reports.vue calls axios directly with a hardcoded URL instead of going through api.js.
Stale test docs. tests/README.md says to run tests from tests/ (that fails) and lists a test_orders.py that doesn't exist.
